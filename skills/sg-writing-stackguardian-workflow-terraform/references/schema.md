# Provider 1.12.3 schema — workflow side

Generated from `terraform providers schema -json` (StackGuardian/stackguardian 1.12.3).
`= {...}` single nested attribute, `= [{...}]` list of objects, `= {key={...}}` map of objects —
all are **attributes** (`name = …`), never blocks. `REQUIRED` / `optional` / `optional+computed`
(computed: the server or a template fills it when you omit it).

Accepted values (not enforced by the provider — the API rejects others at apply):

| Attribute | Values |
|---|---|
| `wf_type` | `TERRAFORM`, `OPENTOFU`, `CUSTOM` |
| `custom_source.source_config_dest_kind` | `GITHUB_COM`, `GITHUB_APP_CUSTOM`, `GITLAB_COM`, `BITBUCKET_ORG`, `AZURE_DEVOPS`, `AZURE_DEVOPS_SP`, `GIT_OTHER` |
| `iac_input_data.schema_type` | `RAW_JSON` (git), `FORM_JSONSCHEMA` (templates); also `NONE`, `RAW_HCL`, `NO_CODE_JSON` |
| `wf_step_input_data.schema_type` | `FORM_JSONSCHEMA` only |
| `environment_variables[].kind` | `PLAIN_TEXT` (`text_value`), `VAULT_SECRET` (`secret_id = "/secrets/<n>"`) |
| `deployment_platform_config[].kind` | `AWS_STATIC`, `AWS_RBAC`, `AWS_OIDC`, `AZURE_STATIC`, `AZURE_OIDC`, `GCP_STATIC`, `GCP_OIDC` (API also: `AZURE_MANAGED_ID_OIDC`) |
| `runner_constraints.type` | `shared`, `private` |
| `user_schedules[].state` | `ENABLED`, `DISABLED` |
| `mini_steps.notifications.email.*`, `mini_steps.webhooks.*` | `approval_required`, `cancelled`, `completed`, `drift_detected`, `errored` |
| `mini_steps.wf_chaining.*` | `completed`, `errored` |
| `vcs_triggers.<event>` map key | `createWfRun` |
| template `source_config_kind` | `TERRAFORM`, `OPENTOFU`, `ANSIBLE_PLAYBOOK`, `HELM`, `KUBECTL`, `CLOUDFORMATION`, `CUSTOM` |
| template / revision `is_public` | `"0"`, `"1"` (strings) |
| `input_schemas[].type` | `FORM_JSONSCHEMA`, `RAW_JSON` |
| runner group `storage_backend_config.type` | `aws_s3` (needs `auth.integration_id`), `azure_blob_storage` |

Data source lookups (all fail at plan when the object does not exist, e.g. `Unable to read
workflow group.`): `stackguardian_connector` (`id`; exposes `settings.kind`, useful for
`kind = data.stackguardian_connector.x.settings.kind`), `stackguardian_runner_group`,
`stackguardian_workflow_group` take `id` (`resource_name` is deprecated there; the group data source
returns only the **leaf** as `id` for nested groups and a null `resource_name` — use it as an
existence check, not to build paths);
`stackguardian_workflow_git` takes the bare workflow `id` + `workflow_group_id` (use it to reference an
existing workflow, e.g. a chaining target, so a typo fails at plan); `stackguardian_workflow_template`
takes `id` but **always fails in 1.12.3** (schema/model mismatch — use
`stackguardian_workflow_template_revision` instead); `stackguardian_workflow_template_revision` takes the bare `<template>:<n>` of your own
org (a `/<org>/` prefix returns a misleading 403, live); `stackguardian_runner_group_token` takes `runner_group_id` (its token is **not** marked
sensitive — mark outputs yourself).
